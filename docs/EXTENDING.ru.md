# Добавление контента

Каталог: `config/stillhunt-content.json` (создаётся первым запуском). Игровые числа и уровни подсказок: `config/stillhunt.json`. Исходные примеры находятся в `config-examples/`.

Завершите матч, отредактируйте JSON и перезапустите сервер. Клиенту не нужно вручную копировать JSON карт: сервер передаёт описания прячущемуся. Текущий матч сохраняет снимок правил и каталога, поэтому изменение файлов не меняет условия уже начавшейся игры.

## Карта без нового Java-кода

Добавьте запись в объект `cards`:

```json
"quiet_steps": {
  "handler": "effect",
  "rarity": 1,
  "weight": 10,
  "category": "light",
  "durationSeconds": 35,
  "names": {"ru_ru": "Тихий шаг", "en_us": "Quiet steps"},
  "parameters": {"effect": "rhythm"},
  "requires": []
}
```

Этот пример запрещает спринт на 35 секунд. `rarity`: 1 обычная, 2 усиленная, 3 редкая, 4 эпическая; это **не** уровень подсказки в черепах. `weight` — относительный вес предложения. Одновременно действует один слот каждой категории: `heavy`, `light`, `task`, `access`; `decoy` предназначен для приманок.

Встроенные обработчики:

| handler | parameters | Результат |
|---|---|---|
| effect | effect: boots / rhythm / noise / silence / quarantine / exam | Ограничение прыжка / спринта, шум, блок сильных подсказок, предметов или уровня 5 |
| task | task: ID из tasks; effect: scavenge / pilgrimage | Серверное задание; блок подсказок / бонусных предметов до выполнения или таймаута |
| decoy | count: "1" или "2" | Временные приманки; не меняют ответы и геометрию карты |

Каждая редкость должна иметь не менее трёх доступных определений. Для расширенного предложения кита рекомендуется четыре. Набор `requires` должен быть подмножеством `profile`, иначе карта не предлагается. Профиль — утверждение автора арены о доступных ресурсах, а не автоматическое доказательство проходимости.

## Новое задание без Java-кода

```json
"granite_quarry": {
  "objective": "break_block",
  "target": "minecraft:granite",
  "count": 4,
  "timeoutSeconds": 90,
  "names": {"ru_ru": "Добудьте 4 гранита", "en_us": "Mine 4 granite blocks"},
  "requires": ["granite"]
}
```

Добавьте `granite` в профиль только если выполнение обеспечено ареной. Затем создайте карту с `handler: "task"`, `parameters: {"task":"granite_quarry","effect":"scavenge"}` и `requires:["granite"]`.

`break_block` засчитывает только события разрушения соответствующего блока назначенным игроком после выдачи задания. Старый инвентарь и действия напарника не засчитываются. `visit_waiting_point` проверяет достижение точки ожидания на сервере. Невыполнимое задание администратор может снять командой `/hunt cancel_effects <игрок>`.

## Новая механика в Java-аддоне

Аддон Fabric должен зависеть от `hidenseek` и регистрировать обработчики в своём `ModInitializer`, до запуска сервера:

```java
ContentRegistry.registerCardHandler("myaddon_signal", context -> {
    // Здесь выполняются дополнительные условия вашего обработчика.
    // context.game(), actor(), target(), definition().
    // true = эффект успешно применён, карту можно потратить.
    // false = отказ без расхода карты. Не меняйте состояние перед отказом.
    return applyMyValidatedEffect(context);
});

ContentRegistry.registerTaskObjective("myaddon_objective", (context, event, value) -> {
    // Только серверное событие назначенного игрока; true = задание завершено.
    return verifyMyObjective(context, event, value);
});

HintRegistry.register("myaddon_hint", context -> {
    // Возвращает Match.Evaluation; null означает отказ без списания.
    // Ответ вычисляется сервером. Не возвращайте координаты укрытия.
    return calculateMyTruthfulAnswer(context);
});
```

Затем добавьте уровень подсказки в `tiers` и описание контента в JSON. API-методы находятся в `ContentRegistry.java` и `HintRegistry.java`. Идентификаторы стабильны и проверяются; повторная регистрация запрещена. JSON не загружает классы, не исполняет скрипты и не выполняет команды.

Расширение подсказок через Java уже доступно; текущая клиентская форма содержит встроенный список параметров. Для совершенно нового вида параметров понадобится клиентская форма аддона или `/hunt action` с JSON. Это ограничение интерфейса, а не обещание произвольного UI из конфигурации.

## Контракт безопасности обработчика

Общая обвязка проверяет матч, роль, фазу, владение картой, слот эффекта, иммунитет, остаток времени, ресурс и cooldown. Обработчик обязан проверять собственные параметры и выполнимость. Нельзя двигать прячущегося, искажать подтверждённую карту или отправлять его закрытые данные искателям. Не трогайте мир из фонового потока. Собственные временные эффекты и сущности должны иметь управляемую очистку.

Перед выпуском расширения добавьте тесты: чужая цель, повторный пакет, отсутствие ресурса, таймаут, восстановление из сохранения и завершение матча.
